# Med Assistant

Локальный медицинский ассистент для анализа лекарственных взаимодействий.
На вход — фото упаковки препарата или его название и вопрос пользователя.
На выход — состав, побочные эффекты, найденные взаимодействия с другими
лекарствами и понятная рекомендация на русском языке от дообученной языковой модели.

## Идея

Языковые модели плохо хранят точные факты: при прямом вопросе о лекарствах
они могут придумать несуществующее взаимодействие или пропустить реальное.
Поэтому в проекте **поиск фактов и их объяснение разделены**:

- **Поиск ведёт детерминированный Python-код** — состав и взаимодействия берутся
  напрямую из баз данных (никаких догадок).
- **Языковая модель только объясняет** уже найденные факты простым языком.

Это исключает галлюцинации в части фактов.

## Алгоритм работы (5 этапов)

```
Фото/название → OCR → Поиск в базах → Дообученная LLM → Рекомендация
```

1. **Подготовка данных** — очистка состава, построение индексов, нечёткая связка
   веществ между двумя базами (rapidfuzz).
2. **Распознавание** — EasyOCR извлекает название препарата с фото упаковки.
3. **Поиск** — pandas ищет состав и проверяет все пары веществ на взаимодействия.
4. **Объяснение** — дообученная языковая модель (Qwen2.5 + LoRA) превращает
   технический отчёт в связную рекомендацию на русском.
5. **Рекомендации** — перебор всех пар препаратов, формирование совета.

## Установка

```bash
git clone https://github.com/<ваш-логин>/med-assistant.git
cd med-assistant
pip install -r requirements.txt
```

### Данные

Проект использует два датасета (не входят в репозиторий из-за размера):

- `Medicine_Details.csv` — препараты, состав, применение, побочные эффекты
- `db_drug_interactions.csv` — пары лекарственных взаимодействий

Положите оба файла в папку `data/` и постройте кэш индексов:

```bash
python src/data_preparation.py
```

## Запуск приложения

```bash
python main.py
```

Откроется веб-интерфейс. Введите названия препаратов (или загрузите фото),
задайте вопрос и нажмите «Анализировать».

### Выбор модели

В настройках интерфейса можно выбрать модель для генерации ответа:

- **Дообученная модель (finetuned)** — Qwen2.5 + обученный LoRA-адаптер
  (требуется адаптер, см. ниже);
- **Ollama** — любая локальная модель, запущенная в Ollama (например `llama3:8b`).

## Дообучение модели

Папка `finetune/` содержит полный пайплайн дообучения языковой модели
методом QLoRA — чтобы модель стабильно выдавала ответ в нужном формате,
на русском языке и с дисклеймером.

| Файл | Назначение |
|------|------------|
| `build_dataset.py` | генерация обучающего датасета из баз данных |
| `Colab_finetune.ipynb` | ноутбук для дообучения в Google Colab |
| `train_qlora.py` | скрипт дообучения (локально) |
| `evaluate.py` | метрики: базовая модель vs дообученная |
| `infer.py` | инференс дообученной модели |

### Как обучалось

Обучение проводилось в Google Colab на GPU Tesla T4 (ноутбук
`Colab_finetune.ipynb`). Базовая модель — Qwen2.5-3B-Instruct, дообучение
методом LoRA на 2000 примерах «технический отчёт → эталонный ответ»,
сгенерированных из баз данных.

Результат — LoRA-адаптер (~100 МБ). Чтобы приложение его использовало,
поместите папку адаптера в `finetune/med_assistant_lora/` и установите:

```bash
pip install torch transformers peft
```

## Технологии

- **EasyOCR** — распознавание текста с упаковки
- **pandas + регулярные выражения** — обработка данных и поиск
- **rapidfuzz** — нечёткое сопоставление названий
- **PEFT + QLoRA** — дообучение языковой модели
- **Qwen2.5** — базовая языковая модель
- **Gradio** — веб-интерфейс

## Дисклеймер

Проект носит учебный и справочный характер. Он не заменяет консультацию врача.
Окончательное решение о приёме лекарств принимает только лечащий врач.
